Compiler Design Architecture

A comprehensive walkthrough of the end-to-end regular expression compilation, automata construction, and execution pipeline.

alt_route Compiler Pipeline Overview

Input Regex String
Phase 1 Lexer
Phase 2 Parser (AST)
Phase 3 Thompson NFA
Phase 4 Subset DFA
Output String Matcher

1. Lexical Analysis (Lexer)

lexer.py

Scans the raw regex string character by character to yield a structured stream of tokens. Crucially inserts explicit CONCAT tokens between adjacent symbols, closures, and groups.

Implicit Concat Insertion "ab" ➔ SYMBOL('a') CONCAT SYMBOL('b')

2. Syntax Parsing & AST

parser.py / ast.py

Uses deterministic recursive descent parsing to construct an Abstract Syntax Tree. Enforces strict operator precedence: Grouping > Repetitions (*, +, ?) > Concatenation > Union (|).

Precedence Rank () > *, +, ? > • (Concat) > | (Union)

3. Thompson NFA Construction

thompson.py / nfa.py

Recursively converts AST nodes into NFA sub-graphs with unique state IDs and ε-transitions. Guarantees single start state and single accepting state per construction block.

Supported Operators Literal, Concat, Union (|), Kleene Star (*)

4. Subset Construction (DFA)

subset.py / dfa.py

Converts NFA into a Deterministic Finite Automaton by computing ε-closures and move transitions across sets of NFA states. Any set containing an NFA accept state becomes a DFA accept state.

Key Operations ε-closure(S), move(S, symbol)

5. Custom String Matcher

matcher.py

Simulates character-by-character transition across DFA states. Does NOT rely on standard library regex modules. Emits full step-by-step execution traces for visual debugging.

Result Status ✓ MATCH / ✕ NO MATCH + Execution Trace
